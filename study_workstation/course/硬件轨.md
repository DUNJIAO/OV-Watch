# 硬件轨：在真机上写 BSP

> 前提：你手上有实物手表 + ST-Link。有实机之后，BSP 不需要仿真——**写完直接烧进手表看效果**。

---

## 一、两条轨怎么分工

| | PC 轨 | 硬件轨 |
|------|--------|--------|
| 写什么 | 页面、事件、状态机、`HWDataAccess` | `BSP/` 下的驱动：屏幕、按键、电源、传感器 |
| 怎么验证 | 截图对比 + 断点看变量 | 手表屏幕、串口打印、用手去操作 |
| 迭代速度 | 秒级，改完 `mingw32-make` 就跑 | 分钟级，要连 SWD、擦写 Flash |
| `HW_USE_HARDWARE` | `0` | `1` |

**两条轨共用同一份 `User/`。** 界面代码一行都不用改——这就是抽象层存在的意义。
差别只有一个宏：

```c
/* User/Func/Inc/HWDataAccess.h */
#define HW_USE_HARDWARE 0    /* PC 轨 */
```

改成 `1`，所有 `#if` 分支就切到 BSP 驱动，同一份页面代码就能烧进手表。

所以合理的顺序是：**页面在 PC 上做（快），BSP 在手表上做（真）**，
两边用同一个抽象层接口对接。

## 三、烧录前必须知道的三个地址

手表 Flash 一共 512 KB：`0x08000000` – `0x0807FFFF`。里面被切成两段：

```
0x08000000  ┌──────────────────────┐
            │  IAP bootloader      │  48 KB，单独一个工程（Software/IAP_F411）
            │  Ymodem 串口升级      │
0x0800C000  ├──────────────────────┤
            │  应用程序 OV_Watch    │  464 KB（0x74000）
            │  ← Keil 的 IROM1     │
0x0807FFFF  └──────────────────────┘
```

三处数字必须一致，任何一处改错都会让手表变砖或者升级功能失效：

| 位置 | 值 | 文件 |
|------|-----|------|
| Keil 的 IROM1 起始 | `0x800c000`，大小 `0x74000` | `MDK-ARM/OV_Watch.uvprojx:279` |
| 应用启动时设的向量表 | `SCB->VTOR = 0x0000C000U` | `Core/Src/main.c:75` |
| bootloader 认为的 app 位置 | `APPLICATION_ADDRESS 0x0800C000` | `IAP_F411/Ymodem/flash_if.h:52` |

**两个会把 bootloader 抹掉的操作，都不要做：**

1. Keil → Options → Debug → Settings → Flash Download 里选 **Erase Full Chip**
2. 把 IROM1 的起始地址改回 `0x08000000`

想升级固件的时候，优先走 **IAP 串口**（按住 KEY1 上电进菜单），那条路根本不碰 bootloader。

## 四、bring-up 清单（单元 7.0）

第一次连手表，按顺序做，每步都要"看到结果"再往下：

1. **装驱动**：插上 ST-Link，设备管理器里应该出现 `STM32 STLink`（没有就去装 ST-LINK Utility 自带的驱动）。
2. **先读不写**：打开 ST-LINK Utility → `Target` → `Connect`。看到 Device 是 `STM32F411CE`、
   Flash size `512KB`，说明 SWD 通了、芯片是活的。
3. **确认擦除方式**：`Target` → `Option Bytes` 里读一下读保护位（应该是 Level 0）。
   烧录时用 `Erase Sectors`，不要 `Erase Full Chip`。
4. **烧参考固件**：`File` → `Open File` 选 `MDK-ARM/output/OV_Watch.hex` →
   `Target` → `Program & Verify`。
5. **看结果**：拔插一下（或按复位），手表跑起来就是成功的。
6. **记下来**：哪个 USB 口、SWD 四根线怎么接的、连一次几秒。以后每次都要重复这套。

> `output/OV_Watch.hex` 在 git 里有一份提交过的原厂固件，随时可以恢复。

## 五、Keil 里点一次烧录，要配这几项

`Project` → `Options for Target`：

| 页 | 设置 |
|----|------|
| Target | IROM1 `0x800C000` / `0x74000`（**别动**） |
| Debug | 选 `ST-Link Debugger`；`Settings` → Port 选 **SW** |
| Utilities | `Use Target Driver for Flash Programming` → ST-Link；`Settings` → 加 `STM32F4xx 512KB Flash` 算法 |
| C/C++ | 头文件路径加上我们 `BSP/` 各模块的 `Inc` |

## 六、第一个 BSP 怎么写、怎么验证

以 LCD 为例（`BSP/LCD/{Inc,Src}`）：

- **函数名照抄参考**：`LCD_Init()`、`LCD_Fill()`、`LCD_SetBackLight()`。名字不一样就接不上
  `HWDataAccess.c` 里已经写好的 `#if HW_USE_LCD` 分支。
- **不要 include LVGL**。BSP 只知道往屏上写像素，不知道什么是"界面"。
- **配一个最小测试 main**，别一上来就跑 LVGL：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    LCD_Init();
    LCD_Fill(0, 0, 240, 280, 0xE11432);   /* 整屏红色 */
    LCD_ShowString(10, 10, "LCD OK", 16, 0xFFFFFF);

    while (1) { }
}
```

参考 `Software/IAP_F411/Core/Src/main.c`——那个 bootloader 没跑 LVGL，照样能在屏上显示菜单和进度条。
**屏幕不通，后面所有模块都没法验证**，所以 LCD 必须排第一。

之后的顺序和验收方式：

| 顺序 | 模块 | 看到什么算成功 |
|------|------|----------------|
| 1 | LCD + 背光 | 整屏变色、亮度能调 |
| 2 | KEY | 串口打印键值 / 屏幕跟着变 |
| 3 | POWER | 串口打印电池电压、电量百分比、插拔充电器时状态变 |
| 4 | RTC | 屏上显示的时间和你电脑/手机一致 |
| 5 | MPU6050 | 摇手表，步数往上走 |
| 6 | AHT21 | 哈一口气，温度湿度变化 |
| 7 | EM7028 | 手指按住传感器，心率有读数 |
| 8 | BL24C02 | 存一个值，断电再上电还在 |
