# 对照表：我们的代码 vs 参考工程

这份表只回答一个问题：**做到第 N 课的时候，我的代码离参考还有多远？**

远不远不是看像不像，而是看**每一处不一样，能不能说出理由**。
说不出来的，就是欠账；说不清理由还越来越多，就是漂移。

---

## 一、工具：一条命令看清差距

```bash
study_workstation/tools/ref_diff.sh               # 和实机参考比（默认）
study_workstation/tools/ref_diff.sh --pc          # 和参考工程的 PC 版比
study_workstation/tools/ref_diff.sh -f HWData     # 看某个文件的完整 diff
study_workstation/tools/ref_diff.sh -f HWData --raw   # 同一份 diff，保留注释和原排版
```

默认比较会先去掉注释、空行和缩进差异（参考工程是 CRLF + Tab，我们是 LF + 空格，
直接 diff 全是噪音），再按行比。

输出里三样东西最有用：

| 列 | 含义 | 怎么看 |
|----|------|--------|
| 状态 | `[~]` 有差异 / `[=]` 一字不差 / `[ ]` 还没做 / `[+]` 我们新增的 | 未做列表就是路线图 |
| 重合 | 去掉注释后，两边一模一样的行数 ÷ 行数多的一边 | **低不一定坏**，见第三节说明 |
| 接口缺/多 | 缺：参考有、我们没有的函数<br>多：我们有、参考没有的函数 | **缺应该永远是 0**；多出来的每一个都要在这里写理由 |

```text
接口：缺失 3 个函数，多出 4 个函数
```

看到「缺失」不为 0 就要停下来问一句：是这个函数本来就不该做，还是我漏了？

### 每课收尾的固定动作

1. 跑一次 `ref_diff.sh`
2. 有新的「多出来」的函数 → 在下面第三、四节找到位置写一行理由
3. 有「缺失」→ 要么这一课补上，要么在第三节标注「哪一课补」

## 三、逐文件说明

### 差异的三种性质

写理由之前先分类，三类处理方式完全不同：

| 类别 | 例子 | 处理 |
|------|------|------|
| **A. 临时欠账** | `Page_Load` 先写成打印 | 记下「哪一课补」，到课必须清零 |
| **B. PC 替代** | `ConnectionError = 0`、`[sim]` 打印、仿真时间源 | 不补；上真机前按第五节切换 |
| **C. 教学改写** | 拆函数、改注释、宏化图标字符 | 永久保留，只要**行为不变** |

**只有 A 类会随时间累积成漂移。** B、C 两类再多也不怕——它们有明确的边界。

## 四、已经发生、且有行为影响的偏差

这几条不属于「改写」，是会改变运行结果的，单独盯：

| # | 偏差 | 表现 | 现状 |
|---|------|------|------|
| 1 | `lv_obj_scroll_by` 挪到子控件之后 | PC 上启动时面板是**收起**的；按参考顺序在 PC 上启动就是**展开**的 | 已确认参考的写法在 8.2 的 PC 模拟里会丢位移（`scroll_by` 只挪已有子控件）。保留我们的顺序 |
| 2 | `ConnectionError = 0` | 仿真里不报连接错误，界面不会弹「未连接」 | 上真机前改回 `1` |
| 3 | `HW_USE_HARDWARE = 0` | 蓝牙/背光/关机只打印 | 上真机前改回 `1` |

第 1 条是**代码写法上唯一一处「同样的控件、不同的行为」**；2、3 两条是开关，
切回真机就一致了。第 1 条的来龙去脉写在 [04_下拉面板.md](04_下拉面板.md) 第五节。

## 五、上真机前必须改回（清单）

按这个顺序，缺一项都会出问题：

1. `Func/Inc/HWDataAccess.h` → `#define HW_USE_HARDWARE 1`
2. `Func/Src/HWDataAccess.c` → 函数表里 `ConnectionError` 改回 `1`
3. 删掉 `main.c` 里的 `HW_Sim_Update();`（真机的 `main.c` 用参考工程那份）
4. 删掉 `Func/Src/pubsub_stub.c`（真机编译的是参考的 `pubsub.c`）

前两项改完，第四课那几个 `[sim]` 打印就会变成真的蓝牙上电、真的背光变化、真的关机。
